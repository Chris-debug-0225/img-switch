# IMG Switch 开源与跨平台发布方案

## 目标和范围

以公开源码仓库和版本发布页提供源码、Windows 安装包、macOS 安装包。普通用户安装后无需自行安装 Python，即可启动控制台、配置中转源并让已接入的 Agent 调用生图能力。源码使用者仍可按文档独立运行引擎。首版覆盖 Windows x64、macOS Apple Silicon 和 Intel；操作系统最低版本由实际构建与安装测试确定，不提前承诺。

已有功能和本机配置需要保留。发布前检查项目文件、构建材料、归档和发布产物，避免包含开发者的本机路径、身份信息、私有配置、密钥、生成记录和无关文件。不得删除第三方软件要求保留的版权或许可声明。

## 方案选择

1. **推荐：保留 Python/Tk 项目，分别构建原生系统安装包和独立引擎。** 复用当前代码和测试，增加打包与发布流程；可执行文件体积会包含运行时，需分别验证系统架构。
2. 仅分发源码和现有独立控制台，要求用户安装 Python。工作量较小，但 Agent 实际生图不是开箱即用，不满足本方案目标。
3. 重写成另一套桌面技术。可以重新设计应用，但成本及兼容风险高，不能仅为打包而推倒重来。

## 用户安装和卸载

- Windows：提供 x64 图形化安装程序，安装控制台和命令行引擎，创建快捷方式；另可按需提供免安装压缩包，但不能以它替代安装程序。安装位置与普通用户权限、更新和卸载行为应在实际验证后明确。
- macOS：分别提供 Apple Silicon 和 Intel 的 DMG，包含 `.app` 和 Applications 入口；用户拖入应用程序目录安装。控制台和 Agent 调用均不得依赖用户预装 Python。
- 卸载或关闭 Agent 接入时只移除本项目管理的文件，不删除无关技能；默认保留用户配置和 API Key，提供清晰的手动彻底清理说明。
- 从旧版本升级时保留配置、接入状态和已有用户数据；升级失败不得让已接入的 Agent 指向不完整的运行时。

## 运行架构

现有 `engine/SKILL.md` 直接调用 `python`，控制台安装技能时也只复制脚本；仅打包 GUI 不能消除用户的 Python 依赖。正式安装包需要增加独立的命令行引擎，并让部署后的 Agent 技能调用该引擎。

- 控制台与命令行引擎分开打包：GUI 负责配置和 Agent 接入，命令行引擎提供原有生图、编辑、模型发现及体检命令，保留可靠的标准输出、错误输出与退出码。
- 首次接入时将对应平台的引擎及技能资源部署到用户目录下由应用管理的稳定位置，并让技能通过可移植入口调用；不能使用开发机绝对路径或临时解包目录。路径含空格、非 ASCII 字符和多个 Agent 同时接入均需覆盖。
- 关闭控制台后引擎仍可用；移动或删除控制台后的行为需与安装形式一致并写入说明。更新时验证新版本后切换，避免删除仍被调用的旧引擎。
- 源码独立使用模式继续支持 Python 脚本；安装包模式生成或安装与之对应的技能入口，不让两种入口互相覆盖用户自定义内容。
- 打包时仅纳入运行所需的明确文件清单；禁止直接把完整 `engine/` 打入发布包。动态导入、Tk 资源和打包后路径需要针对每个平台验证。

## 开源与发布流程

- 使用 GitHub 公开源码仓库和 Releases，源码、许可证、安装说明、问题反馈方式和版本记录对外可见。现有目录尚未初始化 Git，创建仓库、公开发布和首次上传是后续独立步骤。
- CI 在各自操作系统和架构构建，先运行适用的自动测试，再制作安装包并生成 SHA-256 校验文件；以版本标签对应的源码生成发布候选，全部产物完成验证后再发布。工作流权限保持最小化。
- 发布前对仓库快照、源码归档、安装包内容及构建日志执行秘密和路径扫描，并人工复核匹配；检查包内真实内容而非仅检查 `.gitignore`。源码归档不得附带 macOS AppleDouble 或本机扩展属性。
- 检查第三方组件和运行时的再分发条件，在发布包中保留应有的许可证与版权声明。现有 MIT 文件不能单独证明所有源码和依赖已有授权，发布前需确认。
- Git 提交者、标签、CI 日志、应用元数据和签名证书也可能暴露身份；首次提交和每次发布前检查。不能保证签名发行包完全不含发行者身份，需先明确发行身份政策。

## 签名与公证

Windows 安装包和 macOS 应用在缺少正式签名时可能触发系统安全提示，不能宣称可无提示安装。macOS 面向公众顺畅分发通常需要 Developer ID 签名及 Apple 公证；签名证书可能公开发行者身份，与完全匿名要求存在取舍。Windows 签名也可能显示证书发行者信息。

在没有经用户确认的发行身份与证书之前，仅构建并标明未签名的测试包，不伪装成正式签名版本，不绕过用户的系统安全设置。签名证书和公证凭据只放在受保护的 CI secrets 或发布者本机，不能进入仓库、日志和安装包中的配置文件。

## 验收

1. 在干净 Windows x64、macOS Apple Silicon 和 Intel 环境安装，未安装 Python 时启动 GUI，配置模拟源，接入 Agent 并完成一次真实命令链路的模拟生图。
2. 分别验证正常安装、应用关闭后调用、升级、卸载、重新安装、已有配置保留和故障回滚；覆盖含空格及非 ASCII 的用户路径。
3. 执行现有引擎、配置和隐私回归测试，并补充打包资源、CLI 输出、技能入口及无 Python 环境测试；GUI 冒烟与安装器测试必须在对应操作系统运行。
4. 检查源码包和每个平台的最终安装包：文件清单、敏感内容扫描、第三方许可证、版本号和 SHA-256 均正确；证明发布文件来自对应版本源码。
5. 在发布页明确平台、架构、安装步骤、签名状态、已知系统提示及校验方式。未经过签名、公证或平台测试的产物不能描述为已完成对应验证。
