# 开源与跨平台测试安装包实施计划

**目标：** 在保留源码使用方式的同时，让 Windows 和 macOS 安装包内置独立生图引擎，并准备可验证的未签名测试构建。

**架构：** 控制台安装技能时，部署与平台对应的独立命令行引擎和调用入口；源码运行保留现有 Python 流程。两个平台从明确的文件清单分别打包 GUI 和引擎，发布构建保持离线测试和敏感信息检查。

**技术：** Python、Tk、PyInstaller、Windows 安装器、macOS DMG 和 GitHub Actions。

1. **引擎与技能接入**：先增加无系统 Python、路径含空格、升级及配置保留的回归测试；实现独立 CLI 的部署和技能入口；确认 CLI 输出与退出码可供 Agent 使用。
2. **Windows 测试安装包**：仅打包白名单运行资源，构建 GUI 与独立 CLI，创建用户级安装及卸载流程并保留配置；在 Windows 上检查安装、升级、卸载与完整模拟生图链路。
3. **macOS 测试 DMG**：按架构构建 GUI `.app` 与独立 CLI，制作含 Applications 入口的 DMG；在目标架构检查安装、启动、引擎调用与卸载。测试包须清楚标注未正式签名和未公证。
4. **构建编排及文档**：增加分别在目标系统运行的构建及产物上传流程；提供许可证、SHA-256、系统提示、平台限制和本地复现说明；不自动发布正式版本。
5. **隐私与集成验收**：检查源码、归档、安装包、可执行文件和日志中有无真实密钥、本机路径或本机身份信息，保留必要的第三方许可；运行回归测试并如实记录无法在当前环境验证的平台。

**完成标准：** 每个平台的安装包必须在对应系统实际构建并通过安装后的端到端测试，才能宣称该平台可用；架构、签名、公证和未完成项目须明确标注。
